▚ testrazor

Run the tests a change touches.
Trust the green.

A zero-key CLI and GitHub Action that runs only the tests your change can reach and quarantines flaky ones so a green build means what it says.

View on GitHub Quick start

Built with Kiro using spec-driven development. The .kiro/ specs, steering docs and hooks that produced it live in the repo.

What it does

Impact

From a git diff and a source import graph, it selects only the test files a change can reach. Feedback in seconds, not minutes.

Flake

From two or more JUnit runs it finds tests that both pass and fail, scores them and quarantines them. A test that only ever fails is a real bug and is never quarantined.

Gate

One exit code for CI. A quarantined flaky failure does not block. A real failure always does.

See it on a sample repo

$ testrazor impact --root fixtures/sample-repo --changed src/discount.ts
testrazor impact
  selected 2 of 3 test files, 1 skipped (33%)
    run  test/cart.test.ts
    run  test/discount.test.ts

$ testrazor flake --report run1.xml --report run2.xml
testrazor flake
  1 flaky of 3 tests over 2 runs
    flaky  cart :: sums a cart  score 1.00 (1 pass / 1 fail)

$ testrazor gate --report run2.xml --quarantine q.json
testrazor gate
  result: PASS   # the flaky failure is quarantined, it does not block
  ignored (quarantined flaky): 1

$ testrazor gate --report run2.xml   # no quarantine
  result: FAIL
    fail cart :: sums a cart   # a real failure always does

Quick start (60 seconds, no key)

git clone https://github.com/zkasuran/testrazor && cd testrazor
npm ci && npm run build
node dist/cli.js impact --root fixtures/sample-repo --changed src/discount.ts

Flake and gate work for any language that emits JUnit XML. Impact is supported for JavaScript and TypeScript. No account, no API key, no network.
